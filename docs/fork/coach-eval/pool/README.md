# AI-POOL: the larger question pools (AI-PLAN "AI-POOL", FORK-PLAN §1a.85)

Grown batch by batch, one guide area at a time, beside the original sets one folder up (which stay
as they are). Everything here is written from the guide's own text, in our own words.

| File | Split | Format |
|---|---|---|
| `<batch>.toml`, `[[question]]` | **test** (held out) | the advanced-set format (`advanced.toml`), plus optional `needs_clip`, `style`, `origin`; `coach_assist::parse_eval_set` reads it as it is |
| `<batch>.toml`, `[[coach]]` | **test** (held out) | the keyword-coach format (`questions.toml`) |
| `<batch>.jsonl` | **training** | `{"q", "a", "sources", "kind"}` like `training-pairs.jsonl`, plus `"prev"` (the earlier question) for a follow-up |
| `daily-sample.toml` | test | `owner = [...]` (the owner's verbatim questions from `questions.toml`, always in) + `ids = [...]` (held-out pool questions, every batch, evenly spaced over each batch sorted by kind and style), ~150 in all, for a quick GPU run; chosen by `tools/fork/ai-pool-daily-sample.py` (rerun after new batches); not a batch |

- `kind` (advanced): node-role, approach, tweak, tool, multi-step, pro-practice, gap, task, chain,
  picture, creative. (coach): as in `questions.toml`. (pairs): feature, practice, mapping, gap, follow-up,
  task, chain, picture, creative.
- **The three kinds from FORK-PLAN §1a.87** (more pairs without rewording test questions), each
  with a held-out slice in the same batch's `.toml`:
  - `task`: a job that needs two or three sections in order ("grade a log clip, then export it for
    YouTube"); the answer gives each section's steps in that order; `sources` lists them all (≥ 2).
  - `chain`: a follow-up chain; `context = [{q, a}, …]` holds the 1–3 earlier turns, oldest first,
    as the Assistant sends its history; `q` / `a` are the last turn. The overlap check also holds
    out a chain's first question; retrieval is measured on the last earlier question plus `q`.
  - `picture`: `facts` holds a measured-fact sheet in exactly the wording AI4 gives the model
    (`PictureFacts::sheet` in `crates/render/src/picture_facts.rs`: Exposure, White balance,
    Saturation, Skin-tone lines); the answer gives the guide steps that fit those facts. Held-out
    picture questions set `needs_clip = true`.
- **`creative`** (FORK-PLAN §1a.90, AI-PLAN AI4 item 5c): an open-ended creative question no single
  section answers ("replace the person with a translucent ghost"); `sources` = every section the plan
  needs (≥ 2), `must` = the plan's steps plus any gap said plainly with its workaround. Scored apart
  from the lookup questions: `creative_retrieval_covers_the_plan` counts plan sections in
  retrieval's top 8 (not in the recall@5 floor). Every creative item (question or pair) carries
  `family` = its goal family (lower-case words joined by `-`, e.g. `ghost-figure`): one creative goal
  and its 3–5 variants (tripod / handheld, one / many, beginner / pro / Resolve / Premiere / sloppy
  wording). A family is all held out or all training, never both
  (`no_creative_family_is_both_held_out_and_training`). Training recipes (`creative-N.jsonl`,
  kind `creative`) give the full plan, each step a real control / command id. Admitted-gap families
  stay at about a third or less and each gap is listed in `creative-gaps.md`.
- `style`: beginner, pro, resolve-words, premiere-words, sloppy, follow-up, gap: the wording the
  question is written in, so a run can report by style.
- `needs_clip = true`: a good answer depends on the picture or grade on screen (AI4 reads it).
- No `[[coach]]` questions for pages the keyword coach doesn't index on purpose (`NOT_INDEXED` in
  `crates/engine/src/coach_ask.rs`: the AI3-PREP feature pages, practice notes): they could never
  pass; advanced questions and pairs cover those pages. (editing-1 / editing-2 have some from before
  this rule; they stay as measured misses.)
- A gap question is asked only where the guide itself says the feature is not there (its "not yet"
  line); its `must` is that line.

**Checks** (`crates/engine/tests/ai_pool.rs`, run with the engine's tests): every file parses,
sources are real section ids, coach sections are real headings, ids are unique across these files
and the original sets, commands an answer names exist; **no test question, nor a near-copy of one
(similarity ≥ 0.7 of the content-word sets, question words dropped), is in any training file**; the keyword coach and retrieval stay at
their floors (counts that may only go up).

**Review:** a fresh-context reviewer samples each batch before merge; the owner reads a random 30–50
pairs before any tune uses them (Q35 rule).
